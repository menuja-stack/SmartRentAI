## Service 1: Recommendation Engine (Profile-Based "For You")

| Field | Value |
|-------|-------|
| **Port** | `:8001` |
| **Files** | `app.py` (Flask) · `recommender.py` (inference core) |
| **Status** | **Trained** — two saved model files |
| **Algorithm** | Two-stage hybrid: supervised profile→criteria + priority-weighted similarity |
| **Model files** | `profile_model.joblib` (~350 MB) · `property_features.joblib` |
| **Training scripts** | `generate_dataset.py` → `build_property_features.py` → `train_profile_model.py` |

### How it works (two stages)
**Stage 1 — Profile → ideal criteria (supervised)**
- Input: profession, age_group, family_size, has_children, has_vehicle, budget,
  current-district tier, preferred_type, 5 lifestyle priorities (1–5).
- Output: `matched_property_type`, `matched_district_tier` (classifiers) +
  `min_saferent_score`, `max_price`, `min_bedrooms`, `transport_score_min`,
  `hospital_score_min` (one RandomForest regressor per target).
- Trained on **10,000 synthetic rows** that encode Sri-Lankan rental domain rules.

**Stage 2 — Criteria → properties (priority-weighted similarity)**
- Each property gets a 0–1 satisfaction score per dimension (meets a minimum → 1.0;
  within budget → 1.0), weighted by the user's priority ranks, combined as a
  magnitude-aware cosine to the "fully-satisfied" ideal. Handles minimum/maximum
  threshold semantics and missing inventory types gracefully.
- Budget penalty for over-budget listings; preferred-district boost; scores clipped 0–1.

**Cold start**: missing priorities are filled from profession defaults
(`PROF_DEFAULT_PRIORITIES` in `recommender.py`).

### Metrics (Stage 1, 80/20 split on 10k synthetic)
| Target | Type | Metric |
|--------|------|--------|
| matched_property_type | classifier | F1 ≈ 0.69 |
| matched_district_tier | classifier | F1 ≈ 0.81 |
| min_saferent_score | regressor | MAE ≈ 2.6 |
| max_price | regressor | MAE ≈ 140 LKR |
| min_bedrooms | regressor | MAE ≈ 0.0 |
| transport_score_min | regressor | MAE ≈ 2.5 |
| hospital_score_min | regressor | MAE ≈ 2.3 |

Feature importance confirms the model learned the rules: `priority_safety`→saferent
(0.72), `priority_hospital`→hospital (0.69), `budget`→max_price (0.98).

### Endpoints
| Method | Path | Description |
|--------|------|-------------|
| POST | `/recommend` | Profile → top-k ranked properties + match reasons + summary |
| GET | `/recommend/profile-insights/:user_id` | What the model inferred for a user |
| GET | `/health` | Service health check (`model_trained` flag) |

### POST `/recommend` payload
```json
{
  "user_id": 5, "profession": "Doctor", "age_group": "36-45",
  "family_size": "Small Family", "has_children": true, "has_vehicle": true,
  "current_district": "Gampaha", "budget": 150000,
  "priority_safety": 5, "priority_price": 3, "priority_transport": 4,
  "priority_hospital": 5, "priority_space": 4,
  "preferred_type": "house", "preferred_districts": "Colombo,Gampaha", "top_k": 10
}
```
Response: `{ recommendations: [{ property_id, match_score, title, district, price,
bedrooms, saferent_score, match_reasons: [...] }], criteria, profile_summary }`.

### Feedback loop (Phase 7)
`update_preferences.py` reads view/save/enquiry signals from `search_history` and
re-weights each user's `priority_*` scores (action weights view=1, save=3, enquiry=5).
Run on demand or via cron: `python update_preferences.py --commit`.

## Service 2: Price Prediction

| Field | Value |
|-------|-------|
| **Port** | `:8002` |
| **File** | `ai-services/price-prediction/app.py` |
| **Status** | Trained — model files present |
| **Algorithm** | Ensemble: RandomForest + GradientBoosting (average of both) |
| **Model file** | `ai-services/price-prediction/model.joblib` |
| **Encoder file** | `ai-services/price-prediction/encoders.joblib` |

### Training Data
- Default: **2,000 synthetic rows** generated by `generate_synthetic_data()` — realistic Sri Lankan pricing
- Custom: POST `/train` with `{ "data": [...] }` to train on real data
- District base prices baked in (Colombo=45,000, Gampaha=30,000, etc.)
- Auto-trains on first `/predict` call if `model.joblib` is missing

### Input Features

| Feature | Type | Notes |
|---------|------|-------|
| `district` | categorical | LabelEncoder (25 Sri Lankan districts) |
| `property_type` | categorical | LabelEncoder (5 types) |
| `furnished` | categorical | LabelEncoder (3 options) |
| `bedrooms` | int | 0–5 |
| `bathrooms` | int | 0–6 |
| `area_sqft` | float | typical range 200–2000 |
| `has_parking` | 0/1 | binary |
| `has_pool` | 0/1 | binary |
| `has_gym` | 0/1 | binary |

### Model Architecture
```
RandomForestRegressor(n_estimators=200, max_depth=12, n_jobs=-1)
GradientBoostingRegressor(n_estimators=200, learning_rate=0.05, max_depth=5)
Final prediction = (rf_pred + gbr_pred) / 2
```

### Metrics (synthetic 2000-sample training, 80/20 split)
| Metric | Approx Value |
|--------|-------------|
| RMSE | ~6,000–8,000 LKR |
| MAE | ~4,000–6,000 LKR |
| R² | ~0.88–0.93 |

### Endpoints
| Method | Path | Description |
|--------|------|-------------|
| POST | `/train` | Train/retrain on provided or synthetic data |
| POST | `/predict` | Predict rent for given features |
| GET | `/health` | Service health check |

## Service 3: Chatbot

| Field | Value |
|-------|-------|
| **Port** | `:8003` |
| **File** | `ai-services/chatbot/app.py` |
| **Status** | Has trained model file |
| **Algorithm** | ML text classifier (sklearn) — intent detection + rule-based response |
| **Model file** | `ai-services/chatbot/chatbot_model.joblib` |

### What it does
- Classifies user message into intents (search_property, price_inquiry, location_info, general, etc.)
- Returns contextual reply about Sri Lankan rental market
- Persists session messages to `chatbot_messages` table (via backend controller)
- No external LLM dependency — fully offline

### Endpoints
| Method | Path | Description |
|--------|------|-------------|
| POST | `/chat` | Send message, get intent + reply |
| GET | `/health` | Service health check |

### POST `/chat` payload
```json
{ "message": "What houses are available in Kandy?",
  "session_id": "uuid-string",
  "user_id": 3 }
```

| Field | Value |
|-------|-------|
| **Port** | `:8004` |
| **File** | `ai-services/location-intelligence/app.py` |
| **Status** | Fully trained — production ready |
| **Algorithm** | RandomForestClassifier |
| **Model file** | `ai-services/location-intelligence/location_model.joblib` |
| **Stats file** | `ai-services/location-intelligence/district_stats.joblib` |

### Training Data
| Property | Value |
|----------|-------|
| Dataset | `C:\Users\Menuja\Desktop\create new data set\data\final\training_dataset.csv` |
| Records | **401,775** rows |
| Coverage | 25 Sri Lankan districts, 1981–present |
| Target | `disaster_occurred` (binary classification) |
| Features | district, rainfall_mm, humidity_pct, temp_avg_c, month, season, historical stats |

### SafeRent Score Formula
Weighted composite 0–100 (higher = safer):

| Factor | Weight |
|--------|--------|
| Disaster Risk (inverted) | 30% |
| Flood Risk (inverted) | 20% |
| Landslide Risk (inverted) | 15% |
| Hospital Access | 10% |
| Transport Access | 10% |
| Crime Safety | 10% |
| Rainfall (normalised) | 5% |

### Endpoints
| Method | Path | Description |
|--------|------|-------------|
| GET | `/score/<district>` | SafeRent score + factor breakdown |
| GET | `/score/all` | All 25 districts ranked |
| POST | `/compare` | Side-by-side multi-district comparison |
| POST | `/predict-live` | Real-time risk from current weather input |
| POST | `/upload-dataset` | Upload new CSV to retrain |
| GET | `/health` | Service health check |

### Categories
Thresholds as implemented in `compute_safe_score()` (app.py):

| Score Range | Category | Emoji |
|-------------|----------|-------|
| 81–100 | Excellent | 🟢 |
| 61–80 | Good | 🟡 |
| 41–60 | Moderate Risk | 🟠 |
| 0–40 | High Risk | 🔴 |

> The frontend (`SafetyDashboardPage`, `SafeRentWidget`) uses these same cut-offs.
